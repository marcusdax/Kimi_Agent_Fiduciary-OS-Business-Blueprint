## Identity/compatibility contract

- Additive migration only. Existing User/Session/scenario/plan tables and /data volume remain; new AuthSession is separate from legacy unused Session.
- Sign-in obtains a fresh persisted family. Old bearer/refresh tokens intentionally stop working; the UI stores new credentials in memory only, not localStorage.
- Refresh is single-use. Concurrent clients must coordinate refresh; reuse revokes that family. Database contention fails closed and revokes that family rather than reusing a credential.
- `POST /auth/logout` revokes current family; authenticated `POST /auth/logout-all` revokes only that owner's families. Access reads check revocation immediately.
- `POST /documents` and `DELETE /documents/:id`503, never a fake successful upload/deletion.
- Scenario output snapshot is a saved scenario, not a feed cache or a prediction. Fresh public quotes are independent observations with a separate clock/TTL.

## Supply-chain/release policy

Use `npm ci` with committed locks, supported Node22, `npm audit --omit=dev` for actual server runtime separately from full development audit, `npm sbom --omit=dev --sbom-format=cyclonedx` for runtime inventory. Review full advisories and OS image scan rather than hide dev findings by uninstalling tests or downgrading unsupported versions. Do not import optional Better Auth/CASL/decimal/OTel/PDF libraries until their specific design/licensing need is established. Existing app/reviewed code rights unchanged; no source copied from optional repositories.

Official builder sources: https://docs.railway.com/builds/dockerfiles and https://docs.railway.com/deployments/monorepo . Dockerfile is relative to existing isolated service root; `ARG VITE_API_BASE_URL` is public build configuration, not a credential. Official Node image digest checked via https://hub.docker.com/v2/repositories/library/node/tags/22-bookworm-slim . Apt OS packages are not fully snapshot-pinned; reproducible lock/digest is not byte-for-byte hermetic OS assurance.

## Operational recovery/runbook

1. Restrict all release tests to localhost or exact isolated sandbox allowlist. Never point synthetic smoke/drill at customer/production DBs.
2. Check current Railway source/deploy IDs first; stage only sandbox API/web source and Dockerfile path, inspect pending changes and keep existing API volume/key/start command. Do not touch region, size, keys, paid resources or main.
3. Require terminal SUCCESS, correct source commit, health + readiness and6 applied migrations. If build fails, inspect bounded build logs, preserve last healthy runtime and report blocker; do not retry indefinitely.
4. Run strict synthetic smoke with REQUIRE_LIVE=true. Record method replay,401/409/owner isolation, refresh replay/logout, honest disabled documents, provider observedAt/fetchedAt/TTL/units. Confirm no Socket.IO mount and approved/untrusted CORS behavior. Do not print credentials or financial records.
5. Browser acceptance: visible Tools → search Roth → correct basic2026 illustration; dialog Tab/Escape/focus return; opt-in research has no fake launch; dirty plan/tool blocks navigation; mobile320px/200%zoom and chart/table equivalence; Under the hood fields match saved engine/provenance. Parent owns browser review.
6. Incident: pause demo on stale/unavailable critical data or persistence errors; never replace with canned live data. Inspect request IDs/status only, no private inputs. If unhealthy new release, authorized operator may restore previous known healthy sandbox source/config pointer without deleting DB/key. Additive migration remains forward compatible; validate old runtime can ignore new nullable columns/tables.
7. Before production: name an operator and alert destination/SLO; approve retention/access/backup cadence/RPO/RTO and independent key custody, demonstrate restore/rotation using isolated fixtures, validate fleet limits and incident escalation. These choices are not silently invented by this implementation.
